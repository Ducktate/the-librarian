# Setup acceptance checklist

Record evidence in the private automation register and contribution/receipt history.
Each checkpoint is separate; template validity does not establish configured readiness.

- [ ] Private destination has its own remote; ordinary pushes cannot populate public upstream.
- [ ] Company/owner configured; sources inspected with access and coverage limits recorded.
- [ ] Relevant pages have stable IDs, owners, evidence and verification scope; unknowns flagged.
- [ ] Policy, decision authority, canonical home and human review checks adopted by the owner.
- [ ] Each requested agent passes a fresh bounded read and completed v2 shared-intake check.
- [ ] V2 contribution records what/why, repository/module, exact paths and path evidence,
  actual identities/revisions/commits/PRs, real verification, delivery and decision authority.
- [ ] V2 receipts have actual operator/session/machine and run UUID; flags have actionable proof requests.
- [ ] Disposable lifecycle passes: draft rejected until completed, lint, submit, exact retry,
  flag, resolving evidence and filed draft. Authorized publication is checked only within scope.
- [ ] Retained v1 records remain valid/readable; no new v1 records; changed retries are rejected.
- [ ] Validation/tests pass and confidentiality/unsupported claims are reviewed.
- [ ] One report artifact uses explicit date/time zone/as-of and coverage; its executive summary
  is extracted for separate distribution and detailed audit retained privately.
- [ ] One actual recurring job has ID, host/runtime, cadence/time/zone, verified next timestamp/offset,
  DST behavior, duplicate/overlap prevention, owner and disable instructions.
- [ ] Notifications use an authorized destination; daily executive summaries are opt-in.
- [ ] Opted-in daily reporting runs even with empty intake, using --force or a separate report job.
- [ ] Real manual agent run verified; first real scheduled execution observed separately.
- [ ] Failure visibility/private logs and restart from Git/receipts checked.

Report template/configured, read-ready, contribute-ready, scheduled-awaiting-first-run,
verified, failed or blocked checkpoints with evidence. Name missing proof and its owner.
Mocks/dry runs/config files do not qualify real runtime/scheduling. Do not infer full feature
documentation, release readiness or current facts in uninspected repositories.
