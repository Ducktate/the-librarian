# Setup acceptance checklist

Record evidence in your private wiki/operations/automation.md and contribution history.

- [ ] Private destination exists with its own remote; populated data cannot be pushed to the public template by the normal origin command.
- [ ] Company and accountable owner configured; actual source inventory recorded with access limits.
- [ ] Relevant company pages populated from inspected sources, with owners, stable IDs, citations and verification scope. Unknown facts are flagged, not invented.
- [ ] Policy, librarian scope, publication gate and canonical-home migration accepted by the responsible person.
- [ ] Each requested agent passes a fresh-session read check and can deliver a contribution to shared intake; offline/local-only states are visible.
- [ ] Full lifecycle tested: new event, exact retry, missing-context flag, resolving evidence, filed draft, authorized publication and append-only receipt. Disposable demo tests stay outside the real inbox.
- [ ] Validation and tests pass. Review confirms no secrets/customer content or fabricated decision authority.
- [ ] One recurring job actually exists, with ID, host/runtime, cadence, time zone, next run, overlap prevention and disable instructions.
- [ ] Real manual agent run verified; first scheduled execution observed separately. A mock process or dry run is not agent acceptance.
- [ ] Failure reporting and private logs checked. Restart can reconstruct pending work from files and receipts.

If an item is unavailable, identify the missing evidence and responsible person, and label setup partial. Do not replace the requested recurring agent with a document that merely recommends one.
